# 토큰쨩 (TokenChan) 🐱

AI CLI(Claude Code · Codex CLI · Antigravity CLI) 토큰 사용량을 **바탕화면 위 데스크톱 펫**으로 보여주는 Tauri 2 앱.

- 투명·항상 위·프레임 없는 창에 캐릭터만 떠 있음 (드래그로 이동)
- **상황이 생기면** 캐릭터가 말풍선으로 한마디 — 한도 경고·소진, 한도 리셋, 작업 시작/종료, 잠자기/깨기 (몇 초 뒤 자동으로 사라짐)
- **펫을 클릭하면** 폴짝 뛰며 지금 사용량을 말풍선으로 알려줌 (드래그는 그대로 이동)
- **펫 우클릭**(또는 트레이)으로 사용량 패널 — 벤더별 컨텍스트·공식 한도·리셋, 일별 사용량 잔디, 모델 분포. 원하는 자리로 옮겨 두면 위치를 기억
- 세션이 작업 중이면 캐릭터가 타자 모션, 공식 한도 80%↑면 경고 표정, 30분 무활동이면 잠자기
- 시스템 트레이: 펫 보이기 / 사용량 패널 / 설정 / 종료

## 아키텍처

```
crates/usage-core   # 순수 Rust: 어댑터(claude/codex/antigravity) + 집계/단가/컨텍스트 (cargo test 가능)
src-tauri           # Tauri 앱: 창/트레이/IPC + 10초 폴링 스캔 스레드
src                 # React: Pet(캐릭터) + Speech(대사 말풍선) + UsagePanel(사용량) + SettingsPanel
```

### 데이터 소스별 상태

| 소스 | 방식 | 상태 |
|---|---|---|
| Claude Code | `~/.claude/projects/**/*.jsonl` 재귀 파싱, `message.id` dedup, `<synthetic>` 필터. 라이브 상태는 `~/.claude/sessions/*.json` | ✅ 실데이터 검증 |
| Codex CLI | `~/.codex/{sessions,archived_sessions}/**/*.jsonl` 의 `token_count` 이벤트 (누적/델타) + 같은 이벤트의 `rate_limits`(공식 한도) | ✅ 실데이터 검증 |
| Antigravity CLI (`agy`) | `~/.gemini/antigravity-cli/conversations/<uuid>.db` — 대화 하나가 **SQLite 파일 하나**. `gen_metadata` 테이블의 protobuf blob 에서 요청별 토큰·컨텍스트를 읽고, 요청 id 로 dedup | ✅ 실데이터 검증 |

> **Gemini CLI → agy**: Gemini CLI 가 Antigravity CLI 로 전환되면서 어댑터도 교체했습니다.
> 텔레메트리를 켜야만 기록되던 예전과 달리 **설정 없이 항상** 남고, 컨텍스트까지 직접 알려줍니다.

비용은 `crates/usage-core/pricing/prices.json` 단가표(최장 접두사 매칭)로 계산. 설정의 `priceOverridePath`로 덮어쓰기 가능. `costUSD`는 어떤 CLI도 기록하지 않으므로 전부 추정치.

### 공식 플랜 한도 · 작업 중 감지

소스마다 얻는 경로가 달라서 **가능한 것과 아닌 것이 다릅니다.** 셋을 한 덩어리로 묶어 보여주면 거짓말이 되므로 소스별로 나눠 표시합니다.

| | 공식 한도 | 작업 중 감지 |
|---|---|---|
| Claude Code | ✅ **사용량 API 실시간** (`GET /api/oauth/usage`, 인증은 `<홈>/.claude/.credentials.json` 의 토큰) → 폴백 `<홈>/.claude.json` 의 `cachedUsageUtilization` (아래) | ✅ `~/.claude/sessions/*.json` 의 `status` 직독 |
| Codex CLI | ✅ **사용량 API 실시간** (`GET /backend-api/codex/usage`, 인증은 `<홈>/auth.json` 의 토큰) → 폴백 **rollout 의 `payload.rate_limits`** | ✅ **턴 경계 이벤트 직독** (아래) |
| Antigravity CLI | ❌ `quota_manager` 가 서버에서 받아 **메모리에만** 둡니다 (quota RPC 는 실재하지만 토큰이 OS 키링에만 있고 protobuf 요청을 리버싱해야 해서 붙이지 않습니다) | ✅ **턴 경계 이벤트 직독** (아래) |

두 API 호출이 **이 앱의 네트워크 호출 전부**입니다. "홈 직독" 규칙의 예외인데, 예외 없이는 사실을 보여줄 수 없습니다 — 두 소스의 폴백은 서로 다른 이유로 낡습니다. Claude 캐시는 아래 ⚠️ 처럼 세션이 도는 중에도 굳고(굳은 순간의 실측: 캐시 4% · 리셋 3시간 전 vs API 22% · 1시간 45분 남음 — **창 자체가 다른 세대**), Codex rollout 값은 **턴을 돌려야만 갱신**되어 마지막 턴 이후의 리셋과 다른 기기 사용량이 안 보입니다. 각 CLI 자신이 쓰는 것과 같은 엔드포인트이고, 응답이 파일의 값과 같은 모양이라 파싱 어휘를 공유합니다. 인증 토큰도 홈의 파일에서 나오므로 "홈마다 = 계정마다"는 그대로입니다. **토큰 갱신은 하지 않습니다** — 리프레시 토큰이 회전식이라 CLI 의 갱신과 경합하면 로그아웃당할 수 있어, 만료면 그냥 파일 폴백으로 물러납니다 (실측 토큰 수명: Claude 수 시간, Codex 약 9.6일. macOS 의 Claude 는 자격증명이 키체인에 있어 항상 캐시 경로입니다).

Claude 는 예전에 `claude -p "/usage"` 를 실행해 텍스트 출력을 파싱했습니다. CLI 방식은 셋을 잃고 있었고, 파일 직독과 API 는 셋 다 잃지 않습니다:

| | CLI 실행 | 파일 직독 · API |
|---|---|---|
| 발견 | PATH·셸 심에 좌우 — 트레이에서 뜬 앱과 터미널이 다른 답 | 홈 경로만 알면 됨 (홈 탐색과 같은 규칙) |
| 리셋 시각 | `"Aug 1, 3pm (Asia/Seoul)"` — 로컬 타임존 문자열을 되파싱 | RFC 3339 |
| 계정 | 프로세스 하나 = 계정 하나 | **홈마다** — `accountUuid` 가 `oauthAccount` 와 일치 |

```jsonc
"cachedUsageUtilization": {
  "fetchedAtMs": 1786580825099, "accountUuid": "a88ff669-…",
  "utilization": {
    "five_hour": { "utilization": 3,  "resets_at": "2026-08-13T04:30:00Z" },
    "seven_day": { "utilization": 39, "resets_at": "2026-08-15T06:00:00Z" },
    "limits": [ { "kind": "session",       "group": "session", "percent": 3  },
                { "kind": "weekly_all",    "group": "weekly",  "percent": 39 },
                { "kind": "weekly_scoped", "group": "weekly",  "percent": 45,
                  "scope": { "model": { "display_name": "Fable" } } } ] } }
```

`limits[]` 가 `/usage` 화면의 세 줄과 1:1 로 대응합니다. 뜻을 모르는 코드네임 창(`tangelo`, `nimbus_quill` 등)이 형제 키로 섞여 오지만 전부 무시합니다.

⚠️ **캐시라서** Claude Code 가 돌지 않으면 갱신되지 않습니다(실측 갱신 주기: 세션이 도는 동안 5분). 그래서 `fetched_at` 에 읽은 시각이 아니라 `fetchedAtMs` 를 넣어 낡음을 알 수 있게 하고, API 성공값·캐시를 후보로 모아 **서버에서 가장 최근에 받아온 값**을 씁니다 — API 가 살아 있으면 자연히 API 가 이기고, 죽어 있으면(오프라인·토큰 만료·키체인) 캐시가 이깁니다.

⚠️ **세션이 도는 중에도 굳습니다.** 실측(2026-08-13): Claude Code 가 계속 돌고 `.claude.json` 자체는 43분 전에 쓰였는데 `fetchedAtMs` 는 **6시간 전**이었고, 그 사이 5시간 창의 `resets_at` 이 **2시간 전**으로 지나가 있었습니다. 파일의 다른 필드는 갱신되면서 이 캐시만 굳습니다.

API 마저 물러난 채 캐시가 굳으면 리셋 시각을 **직접 계산해서 메웁니다** (`blocks.rs`, 사슬의 마지막 단) — 남은 시간을 0으로 깎으면 "지금 막 리셋된다"는 거짓말이 되고, `limits[]` 에 창 길이가 없어 다음 리셋을 유도할 수도 없기 때문입니다. 규칙은 실측으로 확정했습니다:

```
블록 시작 = 그 블록의 첫 활동을 30분 경계로 내림
블록 종료 = 시작 + 5시간
```

| 내림 단위 | 계산된 종료 | 공식 `04:30:00Z` 와의 차이 |
|---|---|---|
| 없음 | 04:36:33Z | +6.5분 |
| 15분 | 04:30:00Z | **0.0분** |
| 30분 | 04:30:00Z | **0.0분** |
| 60분 | 04:00:00Z | −30.0분 |

첫 활동이 `23:36:33Z` 라 15분·30분이 같은 답을 내서 **둘을 못 가릅니다.** 30분을 택한 근거는 같은 응답의 주간 창이 `06:00:00Z` 로 떨어진 것(30분 격자와 일관)입니다. 틀렸다면 신선한 공식 값과 정확히 15분 어긋나 드러나고, `blocks::ANCHOR_MINUTES` 하나만 고치면 됩니다.

**첫 활동은 사용자 메시지지 assistant 응답이 아닙니다** — 사용량 이벤트만 세면 47분 어긋납니다(위 사례에서 첫 메시지 `23:36`, 첫 응답 `00:16`). 그래서 타임스탬프가 있는 모든 행을 셉니다.

계산으로 메운 값은 화면에서 `~` 로 구분합니다. 확인은 `cargo run -p usage-core --example reset`.

Codex 의 창은 이름 없이 분으로만 옵니다(`limit_name`은 null). **창 길이는 플랜에 따라 바뀝니다** — 같은 계정에서 실측한 값입니다:

| 플랜 | `window_minutes` | `secondary` |
|---|---|---|
| free | 43,200 (30일) | null |
| plus | 10,080 (7일) | null |

**둘 다 창이 하나뿐입니다.** 두 창이 오는 플랜이 있는지는 아직 관측하지 못했습니다. 그래도 오면 대비해 **창이 짧은 것부터** 정렬해, 첫 미터가 늘 "지금 당장 걸리는 한도"가 되게 했습니다.

**Codex 는 턴 경계가 파일에 적혀 있어 추측하지 않습니다.** `~/.codex/history.jsonl` 은 고정 경로이고 프롬프트 제출 때 `{session_id, ts, text}` 한 줄이 붙습니다. 그 `session_id` 가 rollout 파일명의 uuid 와 같아서 디렉토리를 훑지 않고 해당 rollout 을 특정할 수 있고, 그 파일 꼬리에 `task_started` / `task_complete` / `turn_aborted` 가 들어 있습니다 (실측 9파일 38턴: 시작 38 = 완료 33 + 중단 5, 하나도 안 어긋남). 그래서 **응답이 끝나면 즉시** 풀리고, 새 세션도 기다림 없이 잡히며, 동시 세션이 각각 추적됩니다. 이력 저장을 꺼 두면 그 홈의 세션은 작업 중으로 잡히지 않습니다 — 예전엔 파일 크기 변화로 폴백했지만 제거했습니다(아래).

**Antigravity 도 턴 경계가 파일에 있습니다.** `brain/<대화 uuid>/.system_generated/logs/transcript.jsonl` 이 대화마다 따로 있고, 줄이 **턴 도중에 흘러나옵니다**(실측 30분 감시: 9초 턴에 10줄). `USER_INPUT` 이 제출한 그 초에 붙고, `tool_calls` 없는 `PLANNER_RESPONSE` 가 최종 답변입니다 — 실측 61건이 깔끔하게 갈렸습니다(도구 호출 45건은 `content` 없음, 최종 답변 16건은 `tool_calls` 키 자체가 없음).

대화별 파일이라 **동시 대화가 각각** 추적되고, uuid 가 `conversations/<uuid>.db` 와 같아 최근 세션 목록에서도 도는 줄만 짚힙니다.

### 부재를 완료로 읽지 않습니다

세 소스 모두 **양(+)의 완료 신호가 있을 때만** 끝났다고 봅니다. 세션이 목록에서 그냥 사라진 것은 완료가 아닙니다 — 크래시, 강제 종료, 안전망 타임아웃이 전부 같은 모양이라, 그걸 완료로 세면 죽은 세션을 두고 "5분 걸렸어" 라고 말하게 됩니다.

| 소스 | 완료로 인정하는 신호 | 완료가 **아닌** 것 |
|---|---|---|
| Claude | `status` 가 `busy` → `shell`·`idle` | `waiting`(입력·승인 대기) · 파일이 사라짐 |
| Codex | `task_complete` | `turn_aborted`(내가 끊음) · 5분 무음 타임아웃 |
| Antigravity | `tool_calls` 없는 `PLANNER_RESPONSE` | 5분 무음 타임아웃 |

Claude 의 상태 어휘는 `["busy", "shell", "idle", "waiting"]` 네 개이고, 완료 판정은 **허용목록**입니다. 공개 API 가 아니라 값이 늘 수 있는데, 거부목록("busy 가 아니면 완료")이면 처음 보는 값이 전부 완료가 되지만 허용목록이면 알림을 **놓칠 뿐 거짓말은 안 합니다.** 셋 중 승인 대기를 구분할 수 있는 건 Claude 뿐입니다.

### 크기 변화 유도는 제거했습니다

예전에는 턴 경계를 못 읽는 소스를 **감시 파일이 방금 자랐는지**로 유도하고 상태를 `active` 로 표시했습니다. 지웠습니다:

- 그 신호로는 완료·크래시·승인 대기·긴 도구 실행이 **전부 같은 모양**입니다
- 45초 꼬리 때문에 끝난 뒤에도 한동안 작업 중이라고 말했습니다
- 신호 자체가 턴과 무관하게 출렁였습니다 (실측: 입력이 없던 사이에 DB 가 +28KB, 그 다음 **-840KB** — WAL 체크포인트)
- 결정적으로 **소비처가 전부 `busy` 와 똑같이 취급**했습니다. 애매하다는 이름표를 달아 두고 아무도 그 이름표를 보지 않았습니다

이제 턴 경계를 못 읽는 소스는 아무 말도 하지 않습니다.

### 프로세스 생존 확인은 지원하지 않습니다

재료가 한 소스에만 있습니다 — Claude 는 `pid`·`procStart` 를 레지스트리에 남기지만(CLI 자신도 그걸로 확인합니다) Codex 는 pid 를 어디에도 안 남기고, AGY 의 `presence/<uuid>.lock` 은 **프로세스가 없어도 남아 있는 것이 실측**됐습니다(종료 시 정리 안 함). 셋 중 하나만 정확해지는 판정은 "지금 이 벤더는 믿을 수 있나"를 사용자가 외우게 만듭니다.

생존 확인은 결국 **부재를 해석하려는 시도**였는데, 위 원칙이 부재 해석 자체를 그만두므로 필요가 없어졌습니다. 그 대가로 크래시한 세션은 신선도 한계까지(Claude 24시간 / Codex·AGY 5분) 작업 중으로 남아 보입니다 — 다만 **완료로 잡히지는 않습니다.**

### 캐릭터 옆 게이지 — 벤더 하나만

게이지는 **벤더 하나**만 보여줍니다. 링이 3개뿐인데 표현 대상은 벤더 3 × (컨텍스트 + 한도 0~2개)라 다 넣을 수 없고, 섞어 담으면 어느 CLI 숫자인지 알 수 없게 되기 때문입니다. 벤더 비교는 사용량 패널이 맡습니다.

```
평상시                        캐릭터에 마우스를 올리면
  [logo]                        [logo] Claude · fable-5 · 작업 중
   ◕                             ◕ 컨텍스트 16%
   ◔                             ◔ 5시간 15% · 리셋 4h 22m
   ○                             ○ 주간 26%
```

| 요소 | 의미 |
|---|---|
| **맨 위 로고** | 지금 보고 있는 벤더. 작업 중이면 깜빡이고, 세션이 다 끝나 직전 벤더를 계속 보여주는 중이면 흐려집니다 |
| 링 1 | 컨텍스트 소진율 |
| 링 2·3 | **그 벤더의** 공식 한도 (짧은 창부터). Claude 는 5시간 + 주간, Codex free 는 월간 하나 — 한도를 안 주는 벤더(게이지에선 AGY 로 줄여 씀)는 그 줄을 아예 숨겨 열이 짧아집니다 |

리셋까지 남은 시간은 전용 시각 요소 없이 **첫 미터 라벨 뒤에 텍스트**로 붙습니다 — 그 창이 리셋되는 시각이라 의미가 같은 줄이고, 줄을 더 쌓으면 열이 포화됩니다.

라벨은 기본적으로 **호버할 때만** 뜹니다 — 평상시 벤더를 알리는 건 로고 하나뿐이고, 링 색은 이미 소진율 단계(60%/85%에서 주황·빨강)에 쓰고 있어 벤더를 실을 수 없습니다. 항상 펼쳐 두고 싶으면 설정 → **게이지 라벨 상시 표시**를 켭니다.

로고는 `src/assets/vendors/<소스 id>.svg` 에서 옵니다 — 파일명이 곧 `Source` 값이라 벤더를 추가하면 파일만 넣으면 됩니다. `<img>` 로 그리는데, Antigravity 마크가 마스크·필터·내부 id 를 쓰는 멀티컬러라 JSX 로 인라인하면 같은 id 가 문서에 여러 번 들어가 서로를 덮어쓰기 때문입니다. 대신 바깥 CSS 가 SVG 내부 path 에 닿지 않아 **마크 색은 못 바꿉니다** — 파일에 적힌 색이 그대로 나옵니다. 배경·테두리는 요소 자체 속성이라 CSS 로 줄 수 있어서, 검정 마크인 ChatGPT 로고는 브랜드 표기대로 **흰 원판** 위에 얹습니다. 펫은 배경이 사용자 바탕화면이라 밝은 배경에서도 읽히도록 그림자를 겁니다.

**점선 링은 0%가 아니라 "아직 모르는 값"입니다** (컨텍스트가 안 잡힌 경우). 채운 링과 같은 모양이면 소진율 0%로 읽히므로 모양 자체를 다르게 했습니다. 한도 미터는 다릅니다 — 그 벤더가 원래 안 주는 값이라 "없음"을 굳이 보여줄 이유가 없어 줄을 숨기고, 열 높이가 벤더에 따라 달라지는 쪽을 택했습니다.

**벤더 선택 규칙**은 `지금 작업 중 → 마지막으로 움직인 세션 → 오늘 사용량 1위`입니다. **여러 CLI 가 동시에 돌고 있으면 그중 마지막으로 쓴 쪽**입니다 — 라이브 목록의 순서는 활동 순이 아니라 소스를 넣는 순서(항상 Claude 먼저)라 그대로 쓰면 게이지가 "지금 이 세션"을 못 가리킵니다. 두 CLI 를 번갈아 쓰면 근거가 초 단위로 뒤집혀 게이지가 깜빡이므로, 한 번 바꾸면 **5초는 유지**하고 그 사이 들어온 전환은 버리지 않고 홀드가 끝날 때 적용합니다. 특정 벤더로 **고정**하려면 설정 → 게이지에서 고르거나, **게이지 로고를 클릭**해 자동 → Claude → Codex → Antigravity 순으로 전환합니다 (고정 중에는 라벨 끝에 핀 아이콘).

컨텍스트 링은 **세 CLI를 모두 지원**합니다. 셋은 필요한 값을 주는 방식이 다릅니다:

| | Claude Code | Codex CLI | Antigravity CLI |
|---|---|---|---|
| 현재 컨텍스트 | 마지막 응답의 `input + cache_creation + cache_read + output` (유도) | `last_token_usage.total_tokens` (직접) | `1.9.10.1` (직접, 구성 내역까지) |
| 컨텍스트 창 | 단가표 `ctx` → 없으면 관측 승격 | `model_context_window` (직접) | `1.9.10.4` (직접, 실측 256,000) |
| compact | `compactMetadata` 로 실측 (횟수·버려진 양·잠정값 처리) | 미지원 | 미관측 |

Claude 쪽 유도 공식은 compact 직전 실측치(`compactMetadata.preTokens`)와 대조해 검증했고, 오차는 마지막 응답 뒤 사용자 메시지분(최대 한 턴)뿐입니다. Codex 의 `model_context_window` 는 모델 창 전체가 아니라 예비분을 뺀 **실효 창**입니다 (`models_cache.json` 의 272,000 × `effective_context_window_percent` 95% = 258,400 으로 확인).

agy 는 셋 중 가장 친절합니다 — 총계뿐 아니라 **구성 내역**까지 주는데, 실측에서 내역 합이 총계와 오차 없이 맞아떨어졌습니다 (System Prompt 9,870 + Tools 14,992 + Chat Messages 12,967 = 37,829). 다만 **대화의 첫 요청은 값이 엉터리**라(실측 164 — 시스템 프롬프트·툴 정의가 아직 안 잡힘) 컨텍스트 판정에서 제외합니다. 자세한 근거는 `crates/usage-core/src/context.rs` 와 `antigravity.rs` 주석 참고.

단가표에 `ctx` 가 없는 모델은 200k로 가정하되 실제 관측치가 그걸 넘으면 상위 구간으로 자동 승격되므로, 새 모델이 나와도 표를 고치지 않고 스스로 맞춰갑니다. 반대로 소스가 창을 직접 알려준 경우(Codex·agy)에는 그 값이 정답이라 승격하지 않습니다.

### 사용량 패널 (3페이지, 휠·◀▶로 이동)

**1. 현황** — 벤더당 카드 하나. 게이지가 벤더 하나만 보여주므로 **벤더 비교는 여기가 유일한 자리**입니다.

```
✳ Claude  opus-5   [작업 중]   1.2M $4.10
컨텍스트  ▇▇▇░░░░░░  38%
5시간     ▇▇▇▇░░░░░  42%   2시간 12분
주간      ▇▇▇▇▇▇░░░  71%   3일
```

컨텍스트와 공식 한도를 **같은 격자**에 올려 바 시작·끝이 세로로 맞습니다 — 라벨 길이가 달라도 어긋나지 않아야 한눈에 비교됩니다. 리셋은 절대 시각보다 좁고 행동에 가까운 **남은 시간**으로 적고, 정확한 시각은 호버 툴팁에 있습니다. 활성 벤더가 맨 위로 올라오고 테두리가 살아납니다.

**2. 통계·사용량** — **오늘 / 기간 합계**를 나란히, 일별 사용량 잔디, 최근 7일 막대, 오늘 모델 구성비.

```
오늘  1.6M  $4.28        22일  42.3M  $128
오늘 · 입력 91K · 출력 5.6K · 캐시 325K
```

큰 숫자를 하나만 두면 바로 아래 잔디와 기간이 섞여 **전체 합계로 오해**하기 쉽습니다. 둘을 나란히 놓아 기간을 못 박았고, 기간 합계는 통계 페이지에 원래 있어야 할 값이기도 합니다(전에는 잔디를 눈으로 훑어야 총량을 짐작할 수 있었습니다). 기간 합계는 `summary.daily` 를 프론트에서 더합니다 — 일별 값이 이미 다 와 있어 서버 왕복을 늘릴 이유가 없습니다.

오른쪽 라벨은 격자 기간(84일)이 아니라 **기록이 있는 날 수**입니다. 앞쪽이 통째로 기록 없는 구간이면 `84일 42.3M` 로 읽혀 일평균이 어긋납니다 — 잔디 범례와 같은 값(`recordedDays`)을 공유합니다.

잔디는 GitHub과 같은 배치(열=주, 행=요일)입니다. 기간은 **보존기간에서 유도**합니다 — `retentionDays / 7` 을 4~26주로 조여 주 단위로 떨어뜨립니다(격자가 7행이라 어중간하면 마지막 열이 잘립니다). 기본 90일이면 12주(84일)입니다.

| 보존기간 | 격자 |
|---|---|
| 30일 | 4주 (28일) |
| 90일 (기본) | 12주 (84일) |
| 365일 | 26주 (182일) — 패널 폭 상한 |

고정값이었을 때는 보존기간을 줄이면 데이터가 존재할 수 없는 칸이 남고, 늘려도 91일까지만 보였습니다. 열 수와 최대 폭은 컴포넌트가 인라인으로 주고 CSS 는 `margin: 0 auto` 만 담당합니다 — 주가 적으면 가운데 정렬되고, 많으면 칸이 알아서 줄어 카드를 안 넘칩니다.

**기록이 시작되기 전 칸은 점선으로 구분합니다.** 격자가 보존기간을 덮어도 실제 기록은 그보다 짧을 수 있습니다(CLI 를 최근에 깔았으면). 그 칸을 0 과 같은 모양으로 그리면 **CLI 가 없던 날까지 "그날 안 씀"으로 읽힙니다** — 게이지의 점선 링과 같은 규칙으로 채우지 않고 테두리만 남깁니다. 경계는 `summary.first_event_ts`(스캔 범위에서 가장 오래된 이벤트)이고, 범례에 `기록 22일 / 84일`처럼 둘을 같이 적습니다.

색이 진할수록 많이 썼다는 뜻이고 **경고가 아니라서** 패널의 단계 색(주황·빨강)이 아닌 초록 4단계를 씁니다. 칸에 마우스를 올리면 날짜·토큰·비용이 뜹니다.

모델은 **누적 막대 한 줄**로 그립니다. 잔디·주간 막대가 *시간축*인 반면 이건 *구성비*라, 막대를 또 나열하면 같은 종류의 정보로 읽힙니다. 하루 총량을 100%로 잡아 "오늘 뭘 주로 썼나"가 바로 나옵니다.

색은 벤더별이되 **채도를 낮춘 별도 톤**을 씁니다 — 원래 Codex 색(`#10a37f`)이 잔디 초록(`#35d07f`)과 거의 같아서, 같은 화면에서 초록이 "양"이었다가 "Codex"가 되는 혼선이 있었습니다. 조각이 4개를 넘으면 나머지는 `기타`로 묶습니다(좁은 패널에서 실오라기가 되므로).

**3. 최근 세션** — 어느 프로젝트에서 얼마나 태웠는지의 로그. 벤더 페이지는 벤더 단위라 프로젝트를 모르고 통계 페이지는 날짜 단위라 무엇을 했는지를 몰라서, 이 목록만 그 질문에 답합니다.

```
✳ 디렉터리명 변경하고 다시 실행하는데 에러   2분 전
  opus-5 · main                     284M
◍ codex 업데이트 해주세요.           1시간 전
  gpt-5.6-terra · main               802K
◮ Antigravity의 사용량 정책은??      2시간 전
  gem-3.6-flash                      75K
```

**제목은 셋 다 첫 사용자 메시지**입니다 — 폴더명보다 "무엇을 했는지"를 알려줍니다. 없으면 폴더명으로 떨어집니다. 세 CLI 모두 작업 디렉토리도 **정확히** 남겨서 경로를 되짚어 추측할 필요가 없습니다:

| | 세션 id | 작업 위치 | 브랜치 | 제목 |
|---|---|---|---|---|
| Claude | 트랜스크립트의 `sessionId` | 같은 행의 `cwd` | `gitBranch` | 첫 `type:"user"` 행 (아래 필터) |
| Codex | `session_meta.payload.id` | `session_meta.payload.cwd` | `session_meta.payload.git.branch` | 첫 `event_msg/user_message` |
| AGY | 대화 uuid | 첫 스텝의 `19.12.12` | 없음 | 첫 스텝의 `19.2` |

AGY 는 `conversation_summaries.db` 의 `preview` 에도 같은 값이 있지만 실측에서 대화 5건 중 1건만 채워져 있어(요약 DB 갱신이 늦음) **대화 DB 의 첫 스텝**에서 직접 뽑습니다 — 이쪽은 5건 전부에 있습니다. Codex 도 `state_5.sqlite` 의 `threads.title` 에 같은 값이 있지만, 그 DB 는 파일명에 스키마 버전이 박혀 있어(`state_5` → 언젠가 `state_6`) 이미 읽는 rollout 에서 뽑습니다.

**Claude 만 걸러 낼 것이 있습니다.** `type:"user"` 행에 사람이 친 것 말고도 슬래시 명령(`<command-name>`)·그 출력(`<local-command-stdout>`)·시스템 안내(`isMeta`)·`[Request interrupted…]` 가 섞여 들어옵니다. 그대로 쓰면 제목이 `<command-name>/model</command-name>` 이 되므로 태그로 시작하는 것과 `isMeta` 를 건너뛰고 처음 나오는 사람 메시지를 씁니다. 완벽하진 않습니다 — 다른 도구가 주입한 "이어서 작업하세요" 류는 형식상 사람 메시지라 구분되지 않습니다.

제목은 **첫 줄만** 쓰고 80자에서 자릅니다. 붙여넣은 코드블록·JSON 이 그대로 들어오는 게 실측된 사실이라, 안 자르면 목록 한 줄이 무너지고 덩어리가 통째로 요약 payload 에 실립니다.

```sh
sudo apt-get install -y libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

```sh
pnpm install
cargo test -p usage-core   # 코어 로직 테스트 (GUI 의존성 불필요)
pnpm tauri dev             # 앱 실행 (WSLg에서도 동작)
```

### 연결된 계정

**설정 → 계정** 탭에서 이 머신에 로그인된 CLI 계정을 확인하고, 계정 단위로 집계 포함 여부를 켜고 끕니다. 같은 계정을 여러 곳에 설치해 둔 경우 **한 줄로 묶이고**, 그 계정이 어느 홈에 깔려 있는지와 각 홈을 어떻게 찾았는지(표준 위치 / 마커 스캔)까지 보여 줍니다:

```
연결된 계정                                   [다시 검색]
 ☑ ⬤ you@example.com               [Max 5x]
      Claude 로그인
      C:\Users\you                              [표준]
      \\wsl.localhost\Ubuntu\home\you           [표준]
 ☑ ⬤ you@example.com                    [Plus]
      ChatGPT 로그인
      C:\Users\you\.codex                       [표준]
      C:\Users\you\AppData\Roaming\orca\…       [스캔]
```

한 줄에 들어가는 두 값은 **세 소스 모두 같은 의미**입니다 — 오른쪽 칩은 **플랜**, 이름 아래 줄은 **로그인 방식**입니다:

| | 플랜 (칩) | 로그인 방식 |
|---|---|---|
| Claude | `.claude.json` → `oauthAccount.organizationRateLimitTier` (없으면 `organizationType`) → **Max 5x** | `oauthAccount` 가 있다는 것 자체 → **Claude 로그인** |
| Codex | rollout `rate_limits.plan_type` → **Plus** | `auth.json` 의 `auth_mode` → **ChatGPT 로그인** |
| AGY | 없음 (한도 자체를 제공하지 않음) | 로그의 `authMethod` → **Google 로그인** |

플랜 원문 표기가 소스마다 달라(`default_claude_max_5x` vs `plus`) `plan::plan_label` 로 한 규칙으로 다듬습니다. `default_` 와 **벤더 이름(`claude_`)** 을 떼는데, 칩이 놓인 카드가 이미 어느 벤더인지 밝히고 있어 붙여 두면 같은 말이 두 번 나옵니다. 플랜 이름이 안 올 때 **Free** 를 박는 건 agy 뿐입니다 — 거기만 플랜 구분이 없습니다. Codex 는 무료면 `plan_type: "free"` 를 직접 보내고(실측), Claude 는 무료 티어로 Claude Code 를 못 씁니다. 그 둘에서 값이 없다는 건 "무료"가 아니라 **아직 모른다**는 뜻이라 칩을 비웁니다. 값 목록이 공개 API 가 아니라 표 대신 규칙으로 처리합니다 — 처음 보는 플랜(`max_20x` 등)도 원문이 그대로 새지 않습니다.

Claude 만 인증 방식을 적어 두는 필드가 **없습니다.** 대신 그 객체 이름이 `oauthAccount` 이고, API 키·Bedrock·Vertex 로 쓰면 이 객체가 아예 없어 계정으로 잡히지도 않습니다. 그래서 "계정으로 잡혔다 = OAuth 로그인"으로 읽습니다.

플랜 칩이 **어느 계정 것인지** 확실한가는 소스에 따라 다릅니다. Claude 는 계정 파일에서 읽으므로 그 계정 것이 확실하지만, Codex 는 rollout에서 오는 **소스 단위** 값이라 CLI 가 지금 로그인된 계정 기준입니다 — 같은 소스에 계정이 여럿이면 칩을 흐리게 하고 `?` 를 붙입니다. **소진율은 여기 없습니다** — 사용량 패널이 보여주는 것과 겹치기 때문입니다. 같은 소스에 계정이 여럿이면 어느 계정의 플랜인지 구분할 수 없어(CLI 가 지금 로그인된 계정 기준) 배지를 흐리게 하고 `?` 를 붙입니다.

같은 탭에서 **직접 추가한 홈**(소스별 추가·제거)도 관리합니다.

펫 우클릭(또는 트레이) → **연결된 계정**에는 켜고 끄는 체크만 남겨 두었습니다 — 네이티브 메뉴는 한 줄에 문자열 하나뿐이라 위 정보를 담을 수 없어서, 나머지는 전부 계정 탭이 맡습니다. 같은 메뉴의 "계정 설정…"이 그 탭을 엽니다.

계정 식별에 쓰는 파일 (전부 로컬):

| 소스 | 파일 | 얻는 것 |
|---|---|---|
| Claude | `<홈>/.claude.json` — 일반 설정 파일 | `emailAddress`, `accountUuid`, 플랜, rate limit tier |
| Codex | `<홈>/auth.json` | `tokens.account_id`, `auth_mode`, `id_token`(JWT)의 email 클레임 |
| AGY | `<홈>/log/*.log` · `<홈>/cli.log` | `applyAuthResult: email=…, authMethod=…` |

**AGY 만 자격증명이 파일에 없습니다.** 토큰을 OS 키링에 넣기 때문입니다 (`keyringAuth: loaded token` / `ChainedAuth: authenticated via keyring`). 대신 로그인한 계정을 로그에 평문으로 남겨서, 거기서 이메일을 읽어 Claude·Codex와 똑같이 계정으로 묶습니다. 실측에서 로그 6개 중 0바이트짜리 1개를 뺀 5개 전부에 있었습니다. 로그를 하나도 못 읽으면 그때만 `installation_id`로 떨어져 설치본 단위가 됩니다.

참고로 `~/.gemini/oauth_creds.json`과 `google_account_id`는 **AGY 것이 아닙니다** — 구 Gemini CLI가 남긴 것이고(mtime 2025-07-03, AGY 실행에 안 건드려짐), 그 계정 id는 AGY DB 어디에도 없습니다.

설치본 발견은 표준 위치(홈·WSL·직접 추가)에 더해 **마커 파일 스캔**을 씁니다. `%APPDATA%`·`%LOCALAPPDATA%` 등을 깊이 4로 훑으며 `auth.json`+`sessions/`(Codex), `.claude/projects`(Claude), `conversations/`+`installation_id`(agy)를 찾습니다 — 실측 0.8초, 시작 시 1회 + "다시 검색" 할 때만 돕니다.

**기본 포함 규칙**: 표준 위치에서 발견된 계정은 켜고, 마커 스캔으로만 나온 **처음 보는 계정은 꺼둡니다**. 오래된 백업이나 남의 계정이 조용히 합산되는 게 가장 나쁜 실패 모드라서입니다. 반면 이미 켜진 계정의 새 설치본은 그 계정에 합류하므로 자동으로 포함됩니다.

### 재배치된 홈 — 환경변수는 보지 않습니다

CLI 를 격리 실행하는 도구가 홈을 자기 폴더로 돌려놓는 경우가 있습니다 (Codex 는 `CODEX_HOME` 환경변수로). **그 환경변수는 읽지 않습니다.** 읽으면 앱이 보는 범위가 **실행 방식에 좌우되기** 때문입니다 — 터미널에서 띄우면 잡히고 트레이·자동시작으로 띄우면 안 잡혀서, 같은 머신인데 집계가 달라집니다. 세 소스 중 Codex 만 예외를 두는 것도 일관성을 해칩니다.

대신 **세 소스 모두 같은 방법**으로 재배치된 홈을 찾습니다:

| | 방법 |
|---|---|
| `%APPDATA%`·`%LOCALAPPDATA%`·XDG 아래 | **마커 스캔**이 자동으로 찾습니다 (실측: 어떤 래퍼의 Codex 런타임 홈) |
| 그 밖 (다른 드라이브 등) | **"홈 추가…"로 직접 등록** |

즉 홈을 옮겼는데 마커 스캔이 못 닿는 곳이면 한 번 등록해 두면 됩니다. **설정 → 계정** 탭의 "직접 추가한 홈"에서 소스별로 추가·제거합니다 (`extraClaudeHomes` · `extraCodexHomes` · `extraAntigravityHomes`에 저장). 설정에 적어 두면 실행 방식과 무관하게 항상 같은 범위를 봅니다.

**합쳐도 중복 집계되지 않습니다.** 세 어댑터 모두 파일이 아니라 이벤트 단위로 dedup 합니다 — Claude 는 `message.id`, Codex 는 `세션 id + 시각 + 사용량`, agy 는 `gen_metadata` 의 요청 id(실측 19건 전부 고유). 실제로 같은 rollout 이 `~/.codex` 와 재배치된 홈 양쪽에 있던 상황에서 검증했습니다:

| | 스캔 루트 | 이벤트 |
|---|---|---|
| 자동 탐지만 | `~/.codex` | 3건 (다른 홈의 세션은 안 보임) |
| orca 홈 추가 | `~/.codex` + orca | **4건** (중복 1건은 한 번만) |
| 이미 잡힌 경로를 또 적음 | 그대로 2개 | 4건 (경로도 이벤트도 중복 없음) |

## 캐릭터 커스터마이징

캐릭터는 **상태별 이미지 한 장**으로만 그립니다. 코드로 그리는 캐릭터는 없고,
기본 캐릭터도 저장소에 들어 있는 이미지 팩(`src/assets/pet-default/`)입니다 — **그림 파일만 갈아끼우면
코드 수정 없이 캐릭터가 바뀝니다.**

기본 팩은 젤리 슬라임(SVG 8장)이고, 상태마다 몸 색·잔량·표정이 다릅니다 —
대기 민트 / 작업 시안(기포가 끓어오름) / 경고 주황 / 잠 남보라 / 소진 무채(녹아내림) /
초기화 형광민트 / 클릭 라임.

그림 위에는 앱이 얹는 연출이 더해집니다: 상태별 모션(숨쉬기·흔들림·폴짝),
소품 배지(`z` `!` `🪫` `✨`), 그리고 소진율에 따라 느려지는 호흡과 맺히는 땀방울.

캐릭터 관리는 **캐릭터 스튜디오**(설정 → 캐릭터 → "캐릭터 스튜디오 열기")에서 합니다 —
좌측이 캐릭터 목록(내장 기본 캐릭터 포함), 우측이 선택한 캐릭터의 상태별 이미지·상태
사용 여부·대사입니다. 새 캐릭터 만들기, 상태별 이미지 첨부/교체, 상태 켜고 끄기(끄면
idle 폴백), 대사 편집이 전부 여기서 되고, 결과는 아래 팩 폴더에 그대로 저장되므로
폴더를 직접 만들어도 됩니다:

```
<설정폴더>/token-chan/characters/
└─ my-cat/
   ├─ idle.gif        # 필수 — 평상시
   ├─ working.gif     # 작업 중 (없으면 idle)
   ├─ alert.gif       # 한도 경고 (없으면 idle)
   ├─ sleep.gif       # 잠자기 (없으면 idle)
   ├─ exhausted.gif   # 세션 한도 100% 소진 (없으면 idle)
   ├─ refreshed.gif   # 한도 리셋 직후 (없으면 idle)
   ├─ done.gif        # 세션 작업 완료 직후 (없으면 idle)
   ├─ poke.gif        # 클릭 (없으면 idle)
   ├─ speech.json     # 선택 — 이 캐릭터의 대사 (없으면 기본 문구)
   └─ pack.json       # 선택 — 끈 상태 목록 (없으면 모든 상태 사용)
```

상태 사용도 캐릭터의 속성입니다 — 팩은 `pack.json`, 내장 기본 캐릭터는 전역 설정을
씁니다. 팩 폴더를 통째로 공유하면 그림·말투·상태 구성이 전부 따라갑니다.

### 캐릭터별 대사 (`speech.json`)

대사는 **캐릭터의 속성**입니다 — 말투가 외모(팩)를 따라가므로, 모델별로 캐릭터를
바꾸면(캐릭터 탭의 규칙) 대사도 함께 바뀝니다. 파일은 상황 키 → 문구 배열이고,
캐릭터 스튜디오에서 캐릭터를 골라 편집하면 이 파일에 저장됩니다 (손편집도 됩니다):

```json
{
  "enter.working": ["코딩 시작!|화이팅", "일하러 가자~"],
  "poke": ["오늘 {오늘토큰} 썼어"]
}
```

파일에 없는 상황은 설정의 기본 문구 → 내장 기본 순으로 폴백됩니다. `{변수}`·`|`
줄바꿈 규칙은 기본 문구 편집기와 동일하고, 리셋 임박 대사(`resetNotify`)도 활성
캐릭터의 파일을 따릅니다. 팩 폴더를 통째로 공유하면 말투까지 함께 갑니다.

### 지원 이미지 형식

확장자 **`.gif` · `.webp` · `.apng` · `.png` · `.svg`** 다섯 가지만 인식합니다 (`src-tauri/src/commands.rs`의 `CHAR_EXTS`).

| 형식 | 확장자 | 애니메이션 | 비고 |
|---|---|---|---|
| GIF | `.gif` | ✅ | 256색 제한 |
| WebP | `.webp` | ✅ | 애니메이션 가능 · GIF보다 용량/색상 유리 (래스터 중 권장) |
| APNG | `.apng` | ✅ | 풀컬러 + 알파. 확장자가 `.png`면 정적 취급 |
| PNG | `.png` | ❌ | 정적 |
| SVG | `.svg` | ✅ | 벡터 — 배율 250%에서도 안 흐려지고 용량이 작음 (기본 팩이 이 형식). 애니메이션은 **파일 안에** 넣어야 함 |

- **탐색 우선순위는 위 표 순서**입니다. 한 상태에 여러 형식이 있으면 `idle.gif` → `idle.webp` → `idle.apng` → `idle.png` → `idle.svg` 중 **먼저 발견된 하나만** 사용됩니다.
- SVG는 `<img>`로 그려져 바깥 CSS가 내부에 닿지 않습니다. 움직임이 필요하면 SVG 파일 안에 `<style>`과 `@keyframes`를 직접 넣으세요 (기본 팩의 `working.svg` 기포가 그 예시).
- 파일명의 상태 이름은 위 트리의 7개와 **정확히** 일치해야 합니다. 예를 들어 `refresh.gif`는 인식되지 않습니다 — `refreshed.gif`가 맞습니다.
- **영상(mp4·webm·mov 등)은 지원하지 않습니다.** 이미지는 `<img>` 태그로 렌더링되므로 움직임이 필요하면 GIF / 애니메이션 WebP / APNG로 만들어 주세요.
- 파일당 **20MB 상한** (data URL로 인라인하므로 실제 여유는 이보다 작습니다)

### 이미지 제작 가이드

- **투명 배경 필수**
- 권장 256×256px 이상, 하단 중앙이 발 기준점
- 정적 PNG여도 상태별 모션(숨쉬기·타자·떨림)이 CSS로 적용됨

### 모델/벤더별 캐릭터

설정 → "모델별 캐릭터 규칙"에서 접두사 → 팩을 매핑하면 **지금 사용 중인 모델에 따라 캐릭터가 자동 전환**됩니다:

| 접두사 | 효과 |
|---|---|
| `claude` | Claude 모든 모델 (신규 모델 자동 포함) |
| `claude-opus` | Opus 계열만 예외 처리 (더 긴 접두사가 우선) |
| `gpt, o3, codex` | OpenAI 계열 (콤마로 복수 접두사) |

미매칭 모델은 기본 캐릭터로 폴백. "최근 관측된 모델" 칩을 클릭하면 규칙이 자동 추가됩니다.
상태(작업/경고/잠/소진/초기화)는 개별 on/off 가능합니다.

## 실데이터 진단

어댑터가 이 머신에서 실제로 뭘 읽는지 확인할 때 (GUI 없이 동작):

```sh
cargo run -p usage-core --example accounts     # 발견된 설치본·계정 묶음
cargo run -p usage-core --example scan         # Claude 모델별 합계
cargo run -p usage-core --example scan_codex   # Codex 요청별 사용량
cargo run -p usage-core --example scan_agy     # agy 요청별 사용량 + 컨텍스트
```

`agy` 는 별도 설정이 필요 없습니다 — 설치하고 한 번 쓰면 바로 잡힙니다.
